# LLM Gateway 管理页使用指南

管理页地址：`http://127.0.0.1:8317/ui`（服务需已启动）。

页面四个标签页：**供应商**（供应商/渠道/模型/分组管理，日常最常用）、**用量统计**（按工具、按供应商×模型、日趋势）、**请求日志**（每次请求的来源/耗时/token/错误）、**系统**（路由策略、运行时状态、维护开关）。

所有按钮点击都有即时反馈：按下有按压效果、执行中按钮变为"xx中…"并禁用、页面顶端有请求进度条、完成后右上角弹出 ✓（成功）或 ✕（失败）提示。

> 所有增删改操作**立即持久化**到 `config/config.yaml` 并热生效，无需重启。

---

## 1. 整体心智模型

```
供应商 (Provider)     一家模型服务，含 baseUrl + 协议 + 鉴权
  └── 渠道 (Channel)   这家服务的一把 API Key（可多把轮转分摊）
  └── 模型 (Model)     这家服务下你要用的模型清单
分组 (Group)           虚拟模型名：请求组名 = 在组内多家供应商间智能选路
```

接入工具（Agent/IDE 聊天客户端）只需要填：**Base URL** + **网关 Key** + **模型名**。模型名推荐填自动组 `free-fast`——它动态包含你配置的所有模型，加删模型自动同步，永不因某家挂了而不可用。

## 2. 供应商管理（第 1 次配置从这开始）

### 2.1 新增供应商

点 **"+ 新增供应商"**，填：

| 字段 | 说明 |
|---|---|
| ID | 唯一标识（英文小写，如 `zhipu`），之后不可改 |
| 名称 | 显示名（如 `智谱`） |
| baseUrl | 供应商的 OpenAI 兼容地址，通常以 `/v1` 结尾（看供应商文档） |
| 协议 | `openai`（绝大多数家）或 `anthropic`（Anthropic 官方风格端点，自动协议转换） |
| 优先级 | 数字越小越优先被选 |
| 费用档 | free/low/standard/premium，影响路由打分（free 优先试）；手工标注即可 |
| apiKey | 该供应商的 API Key |
| 代理 | 可选，上游需要代理访问时填 `http://host:port` |
| 思考模式 | `跟随`（默认）＝按网关内置名单决定是否注入"关思考"参数；`一律关思考`＝该家每次请求都注入关思考。**该家默认开思考、又频繁出现"要求回传 reasoning_content"的 400 时选这个**（少绕一次）。选"跟随"时网关若撞上这类 400，会自动关思考重发一次并在日志留 `[思考回传]`，不影响请求成功率 |

保存后卡片立即出现。**此时供应商还没有任何模型**，继续 2.3 添加模型。

### 2.2 供应商卡片操作

- **编辑**：改名称/地址/Key 等
- **停用/启用**：临时下线该家（不删配置），停用后路由完全绕开
- **删**：整家删除（连同其渠道、模型条目、分组成员引用，二次确认）
- **渠道（Key 池）**：同一家有多把 Key 时逐个"+ 添加渠道"，可设权重（路由选中概率）。每把 Key 可单独编辑/删除。429 限流时只冷却出问题的那把 Key
- **模型清单**：见下
- **评分**（卡片头部按钮）：直接带着该家第一个启用模型打开「评分沙盘」（见 2.6），不用自己填模型名

### 2.3 添加模型（关键步骤）

供应商卡片内点 **"+ 添加模型"**，填：

| 字段 | 说明 |
|---|---|
| 模型名 | 你在工具里请求的名字，同时是发给上游的名字（上游支持时） |
| 优先级覆盖 | 不填=继承供应商基础优先级 |
| 费用档 | 不填=继承供应商费用档 |
| 日Token限 | 可选，该模型当日 token 上限，超了自动避开（次日重置） |
| 别名 alias | **上游真实模型名与你想用的名字不同时填**。例：上游叫 `Qwen3.8-Flash-Next`（驼峰），你想用小写 `qwen3.8-flash-next` 请求 → 模型名填小写、alias 填驼峰，网关自动映射 |
| 上下文上限 | 可选，该模型能装下的输入 token 数（如 `128000`）。请求输入超限的模型自动跳过——各家免费模型窗口参差不齐（64K~128K），配上它，大请求只发给装得下的，不再白烧尝试次数 |
| 擅长类别 | 可选下拉：写代码 / 分析推理 / 写文档 / 通用。语义路由会把同类请求优先发给对应模型（通用=万金油，不加分不减分） |
| 不进自动组 | 勾选后该模型不进 free-fast 自动组。**图像/视频生成等专用端点模型必勾**（它们不接聊天请求，混进组里被轮到就白烧一次尝试） |

模型行的三个按钮：
- **测试**：直连该供应商×该模型发一句你指定的话（弹窗里可改输入），回显模型的回复原文、耗时、token 消耗。**连通性排障第一入口**——失败会显示上游原始错误
- **编辑**：改参数或改名（改名会同步更新路由条目与分组成员）
- **删**：删除该模型（级联清理），二次确认

模型行还显示实时信息：`P优先级 · 费用档`、alias、今日请求数/token；配了擅长类别时显示中文 tag（写代码/分析推理/写文档/通用）。

**查上游（卡片头部）**：实时拉取该供应商的 `/v1/models`（用其自身渠道 Key 鉴权，不改任何配置），弹窗里：
- 每个上游模型标注 `已配置` / `未配置`——一眼看出这家到底有什么模型、你用了哪些
- **价格**：上游返回价格信息的模型显示费用标（绿色"免费"或黄色 `$X/1M`，悬停看输入/输出单价）；一键配置时自动按价格定费用档（免费→free、≤$1/1M→low、≤$10/1M→standard、更贵→premium），价格未知则继承供应商档
- **配置核对**区：本地配置了但上游清单里找不到的模型会列出（拼错 / 已下架 / 别名 alias 填反了都会在这里暴露）；全部能找到则显示"配置核对通过"
- 顶部搜索框可实时过滤模型名（模型多的供应商好用）
- 未配置行有 **测试 / 一键配置** 按钮：先测再配，配置成功行内立即变"已配置"
- 上游不支持该接口或临时限流时弹窗会显示具体错误（如 HTTP 429），此时用"测试"按钮逐个验证即可

> **重要**：网关不会自动拉取上游模型列表（避免几百个不可调用的模型混进来）。你需要什么模型就手工添加什么。不知道上游有哪些模型名？点"查上游"看清单，照着名字**手工添加**到模型清单。**上游清单里有 ≠ 可以调用**（有的家清单开放但路由不开放），所以推荐"先测试后配置"。

### 2.4 分组（虚拟模型）

页面底部分组表。**推荐只维护一个自动组 `free-fast`**：

- **自动组**（autoAll：✓）：动态包含**所有启用供应商的全部手工模型**，组内按各模型优先级+智能打分选路。加删模型自动同步，无需维护成员表。请求 `free-fast` 时：优先走免费的、快的（速度自动学习）、健康的；某家挂了自动换下一家；主选 2.5 秒无首字自动并发竞速切换
- **静态组**：取消勾选 autoAll 后手工挑成员（供应商×模型×组内优先级），适合"只要这几家"的窄场景

示例：所有工具都配 `free-fast` → 换供应商、换模型、调优先级，工具侧零改动。

### 2.5 上下文自动压缩（管理页无界面开关，改 config.yaml）

Agent 工具（DSH / Claude Code 类）每轮携带全部会话历史，输入随轮次越滚越大（可到 150K+ token），导致小窗口模型接不住、免费配额烧得快。开启后：网关在请求超过阈值时自动把较早历史压成摘要（保留全部 system 提示 + 最近 10 条原文），再把小请求发给模型。同一工具的后续请求走**滚动缓存**，只压缩新增对话，秒级完成。

```yaml
defaults:
  contextCompressThresholdTokens: 100000  # 输入超过 100K token 才触发（0=关闭）
  contextCompressModel: free-fast         # 压缩交给哪个模型/组（推荐组名：免费候选自动轮转+费用守卫）
  keepRecentMessages: 10                  # 最近 N 条消息保留原文
```

改完 config.yaml 后点"系统 → 热重载配置文件"即生效。想确认它在工作：`logs/app.log` 搜"上下文压缩完成"，或看响应头 `X-Gateway-Context-Compressed: true`。模型"忘了"很早的事 → 调大 `keepRecentMessages`。

### 2.6 评分与分摊（供应商页工具条「评分与分摊」按钮）

回答两个平时只能靠猜的问题：**这次请求为什么给了这家模型**、**流量到底有没有分摊到我配的其它模型**。弹窗三个页签：

- **评分沙盘**：用当前运行态（健康/冷却/限流/速度样本）现算一份候选排序，不发真实请求。可指定模型名（组名 / `provider/model` 点名 / 原始模型名）、策略（默认跟随当前）、是否带 tools、是否关键请求、输入 token 估算、来源工具。**只读**：不占半开探测槽、不写留痕库、不改任何运行态——所以随时可点，也不怕点错。
- **最近实测留痕**：网关每次真实决策都算一份排序快照，内存里恒存最近 200 条（重启清空）；落库按抽样比例（默认 5%）持久化，重启后仍能回看"那次为什么给了谁"。这里还能开关留痕、调采样比例与保留天数。
- **分摊对照**：窗口内每个「供应商×模型」**实际被调用了几次/占比** 对比 **按评分应分到几成**。表头上方两行口径是恒显的，别看错：
  - **实际侧**＝该窗口内**全部来源工具**的调用（含网关内部压缩调用 `gw-compress`，它同样吃真实额度）；要只看某一个工具的量，用旁边「来源工具」下拉过滤。
  - **应得侧**＝抽签席 √(分数) 权重的窗口均值，取自**采样库 + 内存环形去重合并**（括号里会显示"采样库 N + 内存 M"），所以重启后不会一片空白；样本不足时该列显示"暂无观测"而不是假装有数——观测太少就把「最近实测留痕」里的采样比例调高（5%→100%）再发几条请求。
  - 再下面一行是**未进抽签席的原因**计数（分数排在席外 / 重复 Key 合占席 / 实测首字慢 / **持续撞限流**），恒显、为 0 的原因不列——它直接回答"为什么分摊不到我"。
  - 底下把**配了却一次没被调用的模型逐个点名**，并区分三种原因：路由条目里被停用 / 该供应商没有启用渠道 / 已启用但零调用（分数排不进抽签席、被撤席、或从未被抽中）。零调用行有「为什么」按钮，点了直接带着该模型去沙盘重放。

表格怎么读：

| 列 | 含义 |
|---|---|
| 综合分 | 13 个因子连乘的结果，条长按相对最高分画 |
| 席 | 进了前 N 个**抽签席**（按模型去重——同模型多把 Key 合占一席）；主选是随机按份额抽中后置顶的，所以"分数第一 ≠ 每次都是它"是设计如此 |
| 应得份额 | 该席在抽签里的权重占比（席内归一化，总和=100%）；未进席显示"不在席" |
| 说明 | 未进席的原因写在这一列：重复 Key 合占席 / 实测首字慢于阈值 / **近 5 分钟连续撞限流 N 次（该家学到的额度≈M 次/分），不占抽签席，仍留在兜底顺序** |
| 因子 | 展开看 13 项连乘明细，低于 1 的降权项标黄、为 0 的标红；`实测中位首字/配置优先级/连续失败/质量问题/该家近5分钟撞墙/该家学到的额度(次/分)` 是诊断值，不参与连乘。撞墙与额度两项显示"没撞过/未学到"就是真的没数据（限流学习是内存态，重启后要靠新请求重新学），不是取数坏了 |
| 门控出局 | 被硬门槛直接剔除的候选与原因（无启用渠道 / 临时停用 / 档位不匹配 / 超上下文窗口），它们根本没进打分，所以不出现在上表 |

**限流怎么进评分**（回答"限流很严重却还往这家怼"）：两道，都不改变"429 不熔断、冷却只冷出事那把 Key"的既有约束。

1. **降权（按渠道）**：`限流压力 = min(1−0.8×窗口压力, 1−0.65×撞墙密度)`，地板 0.2。窗口压力看"当前用量离学到的上限还有多远"，撞墙密度看"近 5 分钟真撞了几次 429"（4 次即满档）。加密度是因为光看窗口压力会漏：撞完一轮流量掉下去、压力归零、因子回到 1.0，于是又被抽中、又立刻 429。密度样本会随窗口滑出自动衰减，不需要人工复位，也不连坐同一家其它 Key。
2. **撤席（按家）**：某家**近 5 分钟撞限流 ≥3 次**且**学到的额度 ≤5 次/分**时，它整个模型不占抽签席，席位让给下一名。撤的是"抽签资格"不是"候选"——兜底顺序里它还在，别的家真不可用时照样能服务，所以不会把任何一家彻底踢掉。偶发几次 429、或额度本来就宽的家不受影响（单测覆盖了这个边界）。

想让"分摊"看得见：`config.yaml` 的 `defaults` 里三个字段（界面里也能直接改，改完下一请求生效）：

```yaml
defaults:
  rankTraceEnabled: true      # false=彻底关闭留痕（评分沙盘仍可用，它无状态现算）
  rankTraceSampleRate: 0.05   # 落库抽样比例 0~1；内存环形缓冲不受此限，始终最近 200 条
  rankTraceKeepDays: 7        # 库内留痕保留天数
```

> 采样比例只在"和默认值不同"时才写进 config.yaml（写盘走最小差异），所以界面上改回默认值后文件里就没有这几行了——回落的默认值与界面显示一致，不是丢配置。

**判断负载有没有铺开**：看分摊对照顶部结论——"前 3 个模型吃掉 X%，另有 N 个已启用的模型零调用"就是没铺开。常见根因不是评分坏了，而是：那几家的模型被标了停用/没有启用渠道（表格已直接区分）、分数进不了前 N 席（去沙盘看它的因子，通常卡在费用档、速度样本缺失或档位不匹配），或被限流/慢阈值撤了席（"未进抽签席的原因"那一行会直接给数量）。

## 3. 用量统计

- **接入工具用量**：按来源工具聚合（自动识别 User-Agent：zcode、claude-code、cline、cursor、浏览器、curl…），看哪个工具消耗多少
- **供应商 × 模型**：每家每个模型的**请求总次数**（成功+失败）、成功次数、输入/输出 token、失败次数（红色 tag，悬停看超时/错误/中断细分），含合计行；**全失败的工具/模型也单列**（成功 0、失败 N），不会因只看成功榜而漏掉
- **日趋势**：每天总量水位条
- **分摊健康度**（页面顶部摘要卡）：窗口内总请求数、实际分到量的「供应商×模型」个数、已启用但零调用的个数、前三占比与结论，末尾恒显**取数口径**（实际侧含 `gw-compress` 等全部来源工具）与未进席原因前三。数据独立取数，它失败不影响下面的用量表；点「打开分摊对照」进完整表格（见 2.6，那里还能按来源工具过滤）
- **按 Key（渠道）用量**（`/api/usage-by-key`）：一家配多把 Key 时，每把 Key 分别扛了多少。一行＝供应商×模型×Key（窗口内最多列 300 行），列含 请求/占比/成功/失败/撞429/输入输出Token/TTFT中位/今日Token预算/冷却
  - **口径恒显在表格上方**：窗口＝页面日期区间（按 `request_log` 落库时间），含网关内部压缩调用（`gw-compress`）与探测背景流量；`失败`＝状态非 OK（与供应商×模型明细同一套口径），`撞429`＝`error_class=RATE_LIMIT`（与路由判限流同源），`TTFT中位`＝该组成功请求 TTFT 的中位数（偶数取中间两值均值）
  - **上线前的历史不摊给任何一把**：`channel_id` 为空的行＝Key 归属功能上线之前落的请求，当时无法知道用的哪把；界面把它们合成一行标"上线前无归属"（灰显、不可按 Key 钻取），并在口径行写明"其中 N 行无 Key 归属（M 次）"。归属上线当天带归属的行很少，那是事实不是故障
  - `今日Token/预算` 与 `冷却` 是**实时运行值**（内存日计数器，重启清零），所以合计行不参与这两列的求和；要看历史某天某把 Key 用日期窗口或日志页 Key 过滤。某行显示"不在当前配置"＝配置里这把已删除/改名，历史用量仍独立保留不被抹掉
  - 失败徽标可点 → 自动跳日志页并带上 供应商+真实模型+Key 过滤
- 时间范围：**日期选择器精确到某一天** / 近7天 / 近30天 / 近一年

## 4. 请求日志

每行一次请求：时间、**来源工具**、请求模型、实际服务的供应商/真实模型、**Key（渠道）**、首字时延（TTFT）、总耗时、token、状态（OK/失败/超时/中断）、尝试次数、错误信息（**已翻译成中文**，悬停看原文）。

**Key（渠道）列**回答"这一发到底用的哪把 Key"：一家多把 Key 时，光看供应商名分不出是"这家慢"还是"这把 Key 被限流"。空值（`—`）＝该行落在 Key 归属功能上线之前，不做猜测回填。展开链路后，路由决策每一步都带 `@渠道id`，重试换了几把 Key 一眼可见。日志页过滤下拉 `Key(渠道)` 可多选（候选自动来自日志实际值）；供应商页每把 Key 行还恒显"今日 N 次 · M tok"（内存日计数器，重启清零）。

过滤工具栏（组合使用）：
- **日期**：选某天看单日流量
- **请求模型 / 真实模型 / 供应商 / 来源工具 / Key(渠道)**：下拉候选自动来自日志实际值，也可自由输入
- **状态 chips**：成功/失败/超时掐断/中断，点击高亮可多选

排障场景：
- 响应慢 → 看 TTFT 哪家大，把它的优先级调低或删掉
- 某工具报错 → 过滤该工具找 FAILED 行看错误列（中文提示，悬停是上游原始错误）
- 想知道实际走的哪家 → 请求模型列看 `模型 → 供应商/真实模型`；尝试次数>1 说明发生过自动切换
- 想知道多把 Key 有没有分摊 → 日志页选该供应商后按 `Key(渠道)` 过滤，或看用量页「按 Key 用量」的占比条
- 怀疑长会话把请求撑爆 → 看该时段 token 列的输入值是否持续增长（Agent 历史累积特征）
- 想知道"那次到底怎么排的序" → 展开该请求的链路，底部会直接内嵌**本次请求的候选排序快照**（同 2.6 的表格与因子展开）。只有被抽样落库的请求才有；没抽中时那里会写明"这次决策没被采样到"，并指路去沙盘用同一个模型名现算一份

## 5. 系统页

- **选路策略**：`auto`（综合，推荐默认）/ `priority`（严格按优先级）/ `latency`（速度优先）/ `weighted`（top3 内加权随机防单点）/ `cost-first`（费用优先）。切换持久化
- **运行时状态**：每供应商×模型的健康视图——正常/熔断/半开、**EWMA 首字时延、出字速度（token/秒）**、连续失败次数、最近错误
- **维护操作**：
  - 刷新模型目录：立即重读配置构建模型索引
  - 重置当日额度：当日预算计数清零（比如想立刻继续被日限挡住的模型）
  - 热重载配置文件：手动编辑过 config.yaml 后不用重启
  - 自动发现开关：临时拉取上游 /v1/models 用（默认关，见 2.3 的说明）

## 6. 典型配置流程（完整示例）

以"接入一家新供应商并让所有工具用上"为例，全程界面操作：

1. 供应商页 → "+ 新增供应商" → 填 ID/名称/baseUrl/协议/优先级/apiKey → 保存
2. 卡片内 "+ 添加模型" → 填模型名（需要别名就填 alias）→ 保存
3. 点模型行 **测试** → 看到模型回复=配置正确；失败看错误信息修正（常见：Key 无效、baseUrl 错、模型名不对）
4. 什么分组都不用动——`free-fast` 自动组已包含新模型
5. 工具里（或不用动，因为工具只配了 free-fast）发起请求验证
6. 请求日志页确认：请求模型 free-fast → 实际走了新供应商，状态 OK

## 7. 小贴士

- **费用档语义**：它只影响路由打分顺序（free 优先），与"是否真的免费"无关，请按实际情况标注
- **优先级排序思路**：免费快的设 0-3，低价的 4-5，贵的兜底 6-9
- **同一家多把 Key**：把权重理解为流量比例（如 key1 权重 2、key2 权重 1 → 流量 2:1）
- **别担心删错**：所有操作都有二次确认且即时生效；删错了重新加回来即可，用量历史不丢
- **日志/数据库越来越大的话**：请求日志自动保留 30 天；想彻底清空历史，停止服务后删除 `config/data/` 目录即可
