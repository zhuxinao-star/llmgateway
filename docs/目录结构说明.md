# 目录结构说明

本文分两半：**前半是仓库布局**（下载者只需要看前半），后半是**作者本机的工作区分区与整理史**（那些目录和脚本不随仓库发布，留在后半只为解释"为什么代码里有 `GW_DB_PATH`、`GW_LOG_DIR` 这类环境变量钩子"）。

## 1. 仓库布局（克隆下来就是这个样子）

「项目根」＝有 `pom.xml` 的那一层，也就是仓库根目录本身：

```
<项目根>\
├── pom.xml                      Maven 工程定义
├── src\main\java\com\gw\        源码（模块划分见第 2 节）
├── src\main\resources\          application.yaml（真正决定端口/日志/库位置）、logback-spring.xml、静态管理页 ui\
├── config\
│   ├── config.example.yaml      配置模板（无密钥）
│   └── config.yaml              你自己填的运行配置（含密钥，已 .gitignore）
├── scripts\                     已发布的 Windows 脚本，见第 3 节
├── target\                      构建产物（不入库）
├── data\                        运行库 llm-gateway.db（脚本默认落这里，不入库）
├── logs\                        app.log + gateway.log（不入库）
└── docs\                        部署指南 / 管理页使用指南 / 本说明
```

`data\` 和 `logs\` 是 `scripts\start.bat` 的默认落点；不带脚本直接 `java -jar` 时，库回到 `config\data\`、日志回到工作目录下的 `logs\`（由 `application.yaml` 的 `gateway.db-path: ${GW_DB_PATH:}` 与 `logback-spring.xml` 的 `${GW_LOG_DIR:-logs}` 决定，留空即用老默认）。

## 2. 源码模块划分

| 包 | 职责 |
|---|---|
| `gateway\` | 接入层：鉴权、请求解析、SSE 写出与保活、错误模型 |
| `router\` | 路由：模型名 → 候选（直接名 / `供应商/模型` 点名 / 组展开） |
| `policy\` | 策略与状态唯一权威：评分因子连乘、EWMA、熔断、429 与限流学习、额度、抽签分摊、决策留痕 |
| `forward\` | 转发：超时预算、attempt 循环、多 Key 轮转、上下文压缩、对冲 |
| `provider\` | 协议适配：OpenAI 直通 + Anthropic 双向转换（含流式事件与 usage） |
| `catalog\` | 目录：定时拉上游 `/v1/models`、余额探测 |
| `stats\` | 统计：异步批量落库、`gateway.log` 每请求一行、按 Key/来源工具聚合 |
| `config\` | 配置：YAML → 校验 → 只读快照；`ConfigWriter` 把管理页改动原子写回 |
| `store\` | SQLite：WAL、异步单写、运行态快照恢复 |
| `admin\` | 管理 REST（供应商/渠道/路由/分组 CRUD + 用量与诊断端点） |
| `util\` | `ProviderClients`：三条出站路径（转发/拉清单/查余额）共用同一个带代理的 HttpClient 工厂 |
| `probe\` | 后台对账：模型可用性探测与自动停用/恢复 |

## 3. 已发布的脚本（`scripts\`）

七个，全部走同一套路径解析规则（细节见《部署指南》第 3 节）：

| 脚本 | 作用 |
|---|---|
| `_env.bat` | 不是给你直接跑的：其余脚本第一行都 `call` 它。它按 `GW_JDK` → `tools\jdk-*` → `JAVA_HOME` → PATH 找 JDK 并验版本 ≥21，按同样思路找 Maven，算出项目根、jar、配置、日志、库、端口 |
| `doctor.bat` | 自检：把上面每一项**实际找到的值**和端口占用情况逐条打出来，还列出七个可覆盖变量。改路径就靠它确认，不用猜 |
| `start.bat` | 起服务：先过六道门（JDK 有 / 版本够 / 有配置 / 有 jar / 端口没被占），缺什么直接说什么并退出；通过后才建目录并新窗口启动，回显 java、logs、db、port 四项来源 |
| `stop.bat` | 按脚本认定的**端口**找进程杀，不按镜像名，绝不会误伤机器上别的 java |
| `status.bat` | 探活 `GET /api/overview`（没有 `/api/health`）；`status.bat log` 看 app.log 末尾 |
| `restart.bat` | stop → 等 2s → start → 等 8s → status |
| `build.bat` | `mvn package -DskipTests` 打 fat jar；构建前检查端口（服务在跑时 jar 被占用写不进去），失败时给出该查的两件事（Maven 仓库连不上 / JDK 不是 21） |

脚本正文一律 ASCII：控制台代码页 936 下，`.bat` 里写中文会被按 GBK 解析而把命令行拆坏（实测过）。中文说明全放文档里。
