## scripts 一览

| 脚本 | 作用 |
|---|---|
| `start.bat` | 起服务（工作目录锁在 `llmGateway\`，日志指到 `logs\`，数据库指到 `data\`，8317 已监听就跳过） |
| `stop.bat` | 按 **8317 端口**找进程杀，不按镜像名，不会误伤别的 java |
| `status.bat` | 探活（没有 `/api/health`，用 `/api/overview`）；`status.bat log` 看最近 20 行 |
| `restart.bat` | stop → start → status |
| `build.bat` | 用自带 JDK+Maven 打 fat jar（先检查服务是否停着，jar 被占用写不进去） |
| `jar-patch.bat ui\|all` | 公司 maven 镜像不在网时的免 maven 热补丁：`ui` 只更新静态资源与资源文件，`all` 先用自带 javac 编译再连 class 一起写，并同步刷新 `target\classes`（否则 `run-unit-tests.bat` 会跑到旧代码）。两处坑已封：源清单必须"带引号+正斜杠"（javac 的 `@argfile` 把反斜杠当转义、按空格分词，本仓路径含空格），`if` 块内取 classpath 要开延迟展开 |
| `run-unit-tests.bat` | 跑 10 个 main 方法自跑式单测套件（不经 surefire） |
| `test-e2e.bat` | 起 mock 上游 + 用 `config\config-test.yaml` 起隔离实例，库落在 `%TEMP%\gw-e2e`，不碰正式库 |
| `deploy-dev.bat` | 把新 jar 与配置模板刷进 `dev\`，**绝不覆盖**已填密钥的 `dev\config\config.yaml` |

脚本正文一律用 ASCII：本机控制台代码页是 936，`.bat` 里写中文会被按 GBK 解析而把命令行拆坏（实测过）。中文说明放这里。

## 数据库搬迁实测（2026-10-03 22:2x）

挪库的动作是"先停服务 → checkpoint → 移动 → 改配置 → 起服务 → 逐表核对"，对不上就原路移回。实测结果：

| 表 | 搬迁前 | 搬迁后（从根 `data\` 读） |
|---|---|---|
| `request_log` | 13920 行，id 1..13920 | 13920 行（起服务后又新增 1 行 = 13921，确认新库在写） |
| `usage_daily` | 601 行，`sum(req_count)` 13072 | 601 行，`sum(req_count)` 13072 |
| `runtime_snapshot` | 666 行 | 666 行 |
| `meta` | 0 行 | 0 行 |

- 移动前 `PRAGMA wal_checkpoint(TRUNCATE)` 得到 `(0,0,0)`、`PRAGMA integrity_check` 为 `ok`，所以移走的是单个干净的 `.db`
- 起服务后 `data\` 下出现 `llm-gateway.db-wal` / `-shm` 并在增长，`GET /api/overview` HTTP 200 —— 说明运行中的进程确实打开的是新路径
